# Delegation

Use only the session's available and authorized agent tools. Do not pin models,
register provider-specific agents or assume tools exist. If delegation is absent
or disallowed, continue serially and call the result self-review.

The parent selects the playbook, maintains progress, integrates changes and checks
the actual artifacts. A child does a bounded task, not a second orchestration loop.
Pass absolute paths resolved from this installed skill, not source-package paths
or slash commands that may be unavailable to a child.

Every brief contains the original goal and stopping point, checkout path, base
and current revision, relevant dirty changes, exact scope, reference/skill paths,
edit permission, allowed test side effects and expected evidence. Preserve the
user's existing authorization limits. Do not pass unnecessary private material.

| Role | Assignment and returned evidence |
| --- | --- |
| Researcher | A distinct question; source/history/thread findings, commands, inference and unknowns. No source edits. |
| Implementer | A justified design and bounded edit scope; focused diff, tests/docs, exact validation and unresolved issues. |
| Reviewer | Intent and exact patch/revision; inspect independently, return confirmed findings, questions and coverage limits. No implementation edits. |

Use separate worktrees or disposable directories for concurrent writers and for
patch applicability or baseline probes. If isolation cannot be established,
serialize work. Separate PostgreSQL instances need separate data directories,
ports and build/install locations where relevant; never share a live database.

Review returned diffs and evidence. Rerun decisive checks on the integrated final
revision; do not accept a child's completion claim as verification. Record which
review was independent. Missing tools or failed child tasks are reasons to narrow
or continue locally, not to fabricate an independent verdict.
